# Concept quality scorecard

> **Editorial assessment, not approval or a usability result.** Every score is a source-only judgment about current written guidance. It does not claim an implemented control, user study, accessibility conformance or an independent human review.

**Source:** [`EVEI2YONE/UI-UX-Design-System-Catalog`](https://github.com/EVEI2YONE/UI-UX-Design-System-Catalog) at commit [`b8e15e1cfb2a`](https://github.com/EVEI2YONE/UI-UX-Design-System-Catalog/tree/b8e15e1cfb2a10ad1ce4c0db4a2f885d39a5bbe9) (current code only; no history assessed). **Assessed:** 2026-11-19 (UTC). **Coverage:** 92 of 92 canonical concepts.

**Snapshot:** 87.9/100 average; 74 strong, 18 good drafts, 0 need revision, 0 need rework. Review queue: 0 P1, 71 P2 and 21 P3. Evidence: 92 E0 entries, meaning no independent review is recorded.

## How to use the scorecard

1. Read the explanation before changing a rating; the short action is a suggested starting point, not a substitute for checking current source.
2. Work through **P1** issues first, then P2, then P3. Priority is risk and rework urgency, not a numerical ranking or implementation approval.
3. Re-score the affected dimensions after editing and record an actual human review or scenario test separately. Keep proposal/status metadata in `catalog/index.json` authoritative.
4. Edit `catalog/concept-scorecard.json`; run `python3 scripts/build_concept_scorecard.py --write`, then the optional workbook generator. Run both checks before submitting.

## Universal criteria

| Code | Criterion | Weight | Check |
| --- | --- | ---: | --- |
| **P** | Purpose and boundaries | 15% | Clear task, scope and use/avoid boundaries |
| **A** | Actionable guidance | 20% | Decisions, conditions and alternatives |
| **C** | Coverage and inclusion | 10% | Relevant states, access and locale concerns |
| **R** | Research and provenance | 15% | Sources, applicability and honest evidence limits |
| **D** | Discoverability and reuse | 10% | Canonical identity, retrieval and related guidance |
| **V** | Verification criteria | 10% | Observable checks for applying the guidance |
| **N** | Signal-to-noise | 20% | Decision-first structure without unnecessary annotation |

**Rating scale (each dimension):** 0 = missing/misleading; 1 = weak; 2 = developing; 3 = good; 4 = strong. Assess context-relevant requirements rather than mechanically penalizing a governance document for lacking a component's keyboard state matrix.

**Total:** `ROUND(25 * SUM(dimension_rating * weight_fraction))`, with weights above. Bands: **85-100 strong**, **70-84 good draft**, **50-69 needs revision**, **0-49 rework**. An unassessed dimension must remain blank in a future assessment; it is not a zero.

**Evidence maturity:** E0 = no recorded independent review; E1 = independent human/source review; E2 = applied implementation or representative task test; E3 = adoption with documented outcomes and owner. Evidence does not add points to the editorial score. All entries are E0 in this snapshot, even if well written.

**Priority:** P1 = immediate editorial contradiction, high-noise or important coverage gap; P2 = targeted improvement; P3 = polish or representative example. A security, privacy or accessibility blocker overrides a high numerical score and requires independent handling.

**Dimension notation:** `P/A/C/R/D/V/N` is the seven 0-4 ratings in the order above.

## Annotation-noise follow-through

The **signal-to-noise** dimension measures how quickly a reader reaches the governing design decision without repetitive warnings, stale claims or unrelated scope. The [commenting and annotations](specifications/patterns/commenting-and-annotations.md) specification now documents dense-thread filtering, marker clustering and an accessible list alternative. Those are **proposed design contracts**, not verified product features or user outcomes.

Applied performance, keyboard navigation and privacy checks remain product-owned. Related guidance: [attention management](specifications/patterns/notifications-and-attention.md) and [cognitive load](knowledge/guidance/cognitive-load-and-decisions.md).

## Revision policy

This assessment is intentionally independent of lifecycle governance: changes here do not set `status`, `owner`, or `reviewed_at` in the canonical registry. An E1-E3 upgrade requires recorded human or implementation evidence; do not promote it based on this file. The spreadsheet [`CONCEPT_SCORECARD.xlsx`](CONCEPT_SCORECARD.xlsx) is an editable working view; the JSON is the maintained rating source. Regenerate with `python3 scripts/build_concept_scorecard_workbook.py` (requires `openpyxl`), and validate it with `--check` whenever JSON changes.
